# AgenLynk 0.4.0 페이즈별 안정화 체크리스트

기준일: 2026-08-13

## 진행 원칙

이 문서는 여러 영역을 동시에 진행하는 로드맵이 아니라, **한 페이즈씩 완료하고 검증한 뒤 다음 페이즈로 넘어가기 위한 실행 체크리스트**다.

- 동시에 진행하는 페이즈는 하나뿐이다.
- 현재 페이즈의 작업·테스트·완료 조건이 모두 충족되기 전에는 다음 페이즈를 시작하지 않는다.
- 각 페이즈가 끝나면 변경 파일, 테스트 결과, 남은 위험을 보고하고 다음 페이즈 진입 여부를 확인한다.
- 각 페이즈는 `Codex 구현 → Codex 테스트 → Grok 검수 → Grok 수정 → Codex 재검토·재테스트 → 해당 페이즈 commit → dev push` 순서로 닫는다.
- Grok 수정은 현재 페이즈 파일로 제한하고, Codex가 diff와 테스트를 다시 확인하기 전에는 commit/push하지 않는다.
- Gateway artifact 전환과 Swift `AppModel` 분해처럼 원인 추적이 어려워지는 변경은 같은 페이즈에 넣지 않는다.
- 기존 사용자 변경인 `src/runtime-installer.js`, `test/runtime-installer.test.js`는 별도 변경으로 보존한다.

## 전체 진행 상태

| 순서 | 페이즈 | 상태 | 핵심 결과 |
| --- | --- | --- | --- |
| 0 | 작업 브랜치와 기준선 | 완료 | `dev`, 테스트 기준선, 소유권/계약 조사 |
| 1 | Characterization freeze | 완료 | 현재 동작을 fixture와 replay로 고정 |
| 2 | Sidecar namespace 추출 | 진행 중 | Gateway 결합을 한 adapter로 제한 |
| 3 | Gateway 1.4.0 release 계약 | 대기 | tag·public client·runtime asset 확정 |
| 4 | 복제 Gateway 제거와 pinned artifact 전환 | 대기 | AgenLynk가 Gateway artifact만 소비 |

| 7 | CI·migration·packaging·release | 대기 | 0.4.0 배포 게이트 완성 |
