# 모니터링 UX 정책

Claude · Codex · Grok · Gateway 세션을 **같은 규칙으로** 보여 주기 위한 기준. 화면·문구를 바꿀 때 이 문서에 먼저 맞추고, 검수는 이 목록으로 한다.

## 1. 역할 (Frontdoor / Worker)
- Frontdoor는 사람이 직접 연 세션, Worker는 다른 세션이 연 세션이다.
- Gateway가 한 번이라도 보고한 세션은 Gateway가 닫은 뒤에도 **Frontdoor로 승격하지 않는다** (worker transcript가 로컬 세션으로 남아도 동일).
- 부모를 모르는 로컬 세션만 Frontdoor 후보가 된다. provider가 다른 부모도 그 provider 아이디로 연결한다.
- **다른 에이전트의 셸 도구에서 띄운 에이전트는 그 세션의 Worker다** (예: Claude Code Bash에서 실행한 `grok -p`, `codex exec`, 중첩 `claude -p`). 부모는 프로세스 계보로 정한다: 띄운 CLI가 자식에게 넘기는 세션 id(`CLAUDE_CODE_SESSION_ID`, `GROK_SESSION_ID`, `CODEX_THREAD_ID`)와 부모 pid 사슬(`~/.claude/sessions/<pid>.json`). 자기 세션 id는 부모가 아니다. 환경 변수는 이 세 id만 id 문자 규칙으로 읽고, 나머지는 저장·기록하지 않는다.
- 부모 연결 우선순위: Gateway/MCP 응답으로 증명된 연결 > 프로세스 계보. 계보만으로는 Gateway worker의 opener를 정하지 않는다(데몬이 우연히 물려받은 환경일 수 있다).
- 부모 없는 일회성 실행(`claude -p`/SDK, `grok -p`, `codex exec`)은 실제 활동이 있으면 지금처럼 Frontdoor로 두되 세션에 `headless: true`를 붙인다(숨기지 않는다).
- **hook으로만 보였고 활동(프롬프트·도구·서브에이전트·권한 요청)도 대화 기록 파일도 없는 세션은 목록에 올리지 않는다.** SessionEnd가 오면 바로, 끝이 안 오면 2분 뒤 잊는다. 사용량 측정 앱처럼 `claude`를 주기적으로 띄우는 도구가 빈 Frontdoor를 쌓지 않게 하려는 것이다. 첫 활동이 오면 그때부터 평소처럼 보인다.
- Gateway가 본 worker id는 `~/.acp-gateway/agenlynk/workers.json`에 남겨, sidecar 재시작이나 기록 보관 0 이후에도 Frontdoor가 되지 않는다. (알려진 한계: 예전에 worker였던 Claude 세션을 터미널에서 `--resume`하면 로컬 Frontdoor로 보이지 않는다.)
- opener를 모르는 Gateway worker는 Frontdoor로 올리지 않되 숨기지도 않고 **연결 미확인 Worker** 한 그룹에 둔다.
- 레인 헤더 첫 줄은 역할(**Frontdoor** / Worker / "Worker · 2단"), 둘째 줄은 이름(사용자 지정, 없으면 자동 이름)이다.
- 레인·배지 이름은 **Frontdoor / Worker**만 쓴다. 중첩(depth≥2)은 "Worker · 2단". "Agent"/"Subagent"로 부르지 않는다. 호출 화살표는 "Worker 호출", 돌아오는 화살표는 "응답".
- 이벤트 종류 `subagent`(CLI 내부 서브에이전트)는 레인이 아니므로 그대로 "서브에이전트"로 쓴다.
- 설정의 **Frontdoor MCP 설치**와 **Worker 에이전트** 목록은 별개다. Frontdoor는 Control MCP(`agent-acp`)가 있을 때만 "설치됨"이고, 가이드 MCP(`agent-acp-guide`)만 있으면 "가이드 MCP만 설치됨"과 설치 버튼을 함께 보인다. Worker 목록의 켜짐·꺼짐은 Worker 사용 여부이며, 목록 위에 그 뜻을 한 줄로 적는다.

## 2. 이름
- provider는 **아이콘**으로 보여 준다(Claude / Codex / Grok). 이름 텍스트에 provider를 반복하지 않는다.
- Frontdoor 이름: 사용자 지정 > 작업 폴더명 > 지정 제목.
- 세션 이름: 사용자 지정 > CLI 자체 제목(Claude ai-title) > 최근 프롬프트 앞 60자 > 작업 폴더명 > "새 세션".
- 도구 호출 문자열인 제목(`tool_call` / `function_call`이 들었거나, 공백 없이 `/`로 이은 이벤트 경로 `custom_tool_call/exec`)은 Frontdoor·세션 어느 이름으로도 쓰지 않고 다음 순위로 넘어간다. 경로를 언급한 문장("fix src/a.swift")은 이름이다.
- 원시 세션 id(`local:codex:01a0…`)는 이름으로 쓰지 않는다. tooltip에만 두고 "세션 id: " 접두어를 붙인다.
- provider 원문(`codex`)을 tooltip에 쓰지 않는다. 표시 이름(Codex)을 쓰고, 모르는 provider는 "알 수 없는 CLI".
- 사용자는 Frontdoor와 세션 모두 이름을 바꿀 수 있고(연필 / 레인 우클릭), 비우면 자동 이름으로 돌아간다.

## 3. 상태 문구
| status | 문구 |
|---|---|
| running | 실행 중 |
| waiting_permission | 권한 대기 (Codex 샌드박스 승인 포함) |
| waiting_input | 입력 대기 (에이전트가 사용자에게 질문) |
| idle, ready, end_turn, completed(세션) | 대기 |
| closed | 종료 |
| error | 오류 |
- 원문 status 문자열(`waiting_permission` 등)을 화면·tooltip에 노출하지 않는다. 목록에 없는 status는 "알 수 없음".
- 메뉴바도 같은 표를 쓴다: 권한 대기와 입력 대기를 합쳐 "응답 대기"로 쓰지 않는다.
- 태스크·요청 레코드의 completed만 "완료"로 쓴다.
- 활동 머리글: "생각 중", "응답 생성 중", "권한 대기 중", "입력 대기 중", "취소 중", "실행 중", "대기 · 다음 입력을 기다림", "종료됨". 대기·종료를 "완료"로, 취소 중을 "실행 중"으로 쓰지 않는다. 목록에 없는 status는 "알 수 없음".
- Frontdoor 상태 배지: 멤버가 권한/입력을 기다리면 "권한 대기 N"/"입력 대기 N"(둘 다면 "권한 대기 N · 입력 대기 M", 주황), 실행 중이면 "실행 중", 모두 닫혔으면 "종료", 그 밖은 "대기". 사이드바 행은 이 문구를 **항상** 이름 옆에 보인다(대기와 종료를 구분). 사이드바 둘째 줄은 "Worker 2 · 실행 중 2 · 작업 토큰 34K"(기다리는 세션은 실행 중에 세지 않음). Frontdoor를 고르면 기다리는 Worker를 먼저 선택한다.
- 한 이벤트의 상태는 요청 결과가 이긴다: 표시 = 요청 결과 ?? 이벤트 상태. 거부된 권한 옆에 "완료"를 쓰지 않는다.
- 도구 상태: pending "시작 전", running "실행 중", completed "완료", failed "실패", cancelled "취소됨".

### 색 (한 표, `statusColor`)
| 의미 | 색 |
|---|---|
| running, restoring, 승인됨 | 초록 |
| waiting_permission, waiting_input, 요청 대기 | 주황 |
| idle, ready, end_turn, completed, closed, cancelling, 응답됨, 취소됨 | 회색(secondary) |
| error, failed, 거부됨, 연결 끊김 | 빨강 |
- 파랑은 선택·강조(accent)에만 쓴다. provider 식별색도 파랑을 쓰지 않는다(Codex는 청록, Claude 주황, Grok 보라). closed 아이콘은 stop.circle(체크 표시 아님).

### 경고 배지
- 알려진 코드만 전용 문구(`permission_policy_partial` → "읽기 전용 부분 적용"). 모르는 코드는 배지 "경고", tooltip은 메시지, 없으면 "자세한 설명이 없는 경고입니다." 원문 코드를 보이지 않는다.
- 권한 요청 결과 어휘는 approved / denied / cancelled로 고정하고 권한 요청 대기 / 승인됨 / 거부됨 / 취소됨으로 보인다. 결과를 알 수 없는 응답은 "응답됨". 거부·취소를 "완료"로 보이지 않는다.
- 판정 근거: hook은 다음 이벤트(도구 실행 = 승인, PermissionDenied = 거부, 턴 종료 = 취소), Gateway는 고른 option의 kind(allow_* / reject_*, 선택 없음 = 취소).
- 도구 결과도 성공/실패를 구분한다(Codex의 non-zero exit, 샌드박스 거부는 실패).

## 4. 세션 수명
- 턴을 마친 세션은 **대기** 상태로 `대기 세션 유지 시간`(기본 30분, Gateway idle unload와 같음) 동안 남긴다. 기준 시각은 마지막 활동(턴 종료) 시각이다. 재사용 시 cold start를 피하기 위함.
- 목록에서 빠진 세션이 메모리 로그에 남는 시간도 같은 값이다. 그보다 오래된 것은 "지난 기록"에서 본다.
- 종료가 확인된 세션(SessionEnd hook, 프로세스 종료, Gateway session_closed)은 바로 기록으로 옮긴다.
- 이 규칙은 provider와 hook 유무에 관계없이 같다.

## 5. 타임라인
- 한 줄로 계속 스크롤한다(페이지 없음). 맨 아래 표식이 보이면 새 이벤트를 따라가고(마지막 이벤트가 바뀔 때마다, 같은 도구 그룹이 늘어날 때 포함), 위로 올리면 멈추며 "최신으로"로 돌아간다. 맨 위에 닿으면 이전 기록을 더 불러오고, 불러오기 전 맨 위에 있던 **이벤트**에 화면을 고정한다.
- 메모리에 두는 이전 이벤트는 세션당 5,000개까지다. 그보다 위로는 더 불러오지 않고, 맨 위에 "처음 이벤트" 대신 "이전 이벤트는 세션당 5,000개까지 보관합니다"를 쓴다.
- 도구 호출은 **짧은 헤더**(도구명 + 인자 앞 ~30자 + 상태 기호)로만 보여 주고, 출력은 인스펙터에서 본다.
- 같은 턴에서 연속된 도구 호출은 대표 한 줄로 묶는다: "도구 N개 · 실행 중: …"(hook으로 실시간 수신된 실행 중 호출이 먼저, 그다음 실행 중인 것), 실행 중인 것이 없으면 "도구 N개 · 마지막: …". 실패가 있으면 개수를 붙인다. 턴을 모르는 호출끼리는 묶지 않는다. 그룹 tooltip은 "도구 호출 N개 펼치기"/"접기".
- hook으로 받은 도구 호출(이벤트 `sources`에 "hook")과 그런 호출이 든 그룹 헤더에는 작은 번개 표식을 붙이고 tooltip은 "hook으로 실시간 수신".
- 이전 기록을 불러올 때 맨 위가 펼친 그룹 헤더면(가리키는 이벤트 없음) 그 그룹의 첫 호출에 고정한다. 세션 상세 창의 목록도 대시보드와 같은 따라가기·"최신으로"·고정 규칙을 쓴다.
- 시퀀스에서 이벤트(노드·도구 그룹·화살표)를 고르면 그 이벤트의 세션도 선택된다. "선택한 세션"과 인스펙터가 같은 것을 설명한다. 레인을 누르면 세션만 바꾸고 고른 이벤트는 그대로 둔다(우클릭: 세션 상세 열기 / 이름 바꾸기). 그래서 고른 이벤트가 선택한 세션의 것이 아니면 인스펙터 이벤트 칸 첫 줄에 "이 이벤트는 <세션 이름>의 것입니다."를 쓴다.
- 시퀀스를 클릭해 포커스를 준 뒤 위/아래 방향키는 행을 옮기며 그 행의 이벤트(도구 그룹이면 대표 호출)를 **선택**한다. 좌/우는 레인을 스크롤한다. 안내 문구: "클릭 후 방향키로 이벤트를 고릅니다".
- 레인 헤더에 세션 상태 점을 두고, 권한/입력 대기면 상태 문구를 함께 보인다.
- 빈 타임라인: capabilities에 timeline이 없으면 "이 소스에서는 이벤트 타임라인을 볼 수 없습니다". 지난 기록을 여는 중이면 "기록 불러오는 중…", 실패하면 "기록을 불러오지 못했습니다".
- 출력이 인스펙터에서 잘리면(4,000자) "전체 출력 보기…"로 전체 본문을 시트에서 선택·복사할 수 있게 한다.
- 권한 요청, 메시지, 생각, 턴 경계는 묶지 않는다.
- 턴이 끝나면 열린 도구 호출은 턴 결과(완료/취소)로 닫는다 — 스피너가 남지 않는다.
- 이벤트 종류는 한국어로: 턴 시작, 턴 종료, 사용자 입력, 응답, 생각, 도구 호출, 권한 요청, 입력 요청, 서브에이전트, 계획, 컨텍스트 압축, 오류. 목록에 없는 종류는 "알 수 없는 이벤트".

## 6. 사용량
- "세션 누적 토큰"(입력은 cache 포함 · 출력)과 "최근 요청 컨텍스트"를 구분해 쓴다.
- 창 크기를 모르면(Claude) 게이지 대신 "최근 요청 컨텍스트 N 토큰 (창 크기 미제공)".
- 대화 기록 일부만 읽은 합계는 `+`를 붙이고 tooltip으로 설명한다.
- **작업 중 사용량과 예상치**: 진행 중인 턴은 "이번 턴 N 토큰 · M분째". 완료된 턴이 2개 이상이면 "예상 약 X (지난 k턴 중앙값) · 예상의 N%"와 진행 막대(초과 시 주황)를, 컨텍스트 창을 알면 "컨텍스트 약 K턴 여유"(최근 턴당 증가량 중앙값 기준)를 보인다.
- Grok은 턴이 끝나야 토큰을 확정하므로 진행 중에는 "이번 턴 집계 중"으로 쓴다(추정하지 않는다). 사용량이 아직 없어도 진행 중인 턴이 있으면 사용량 영역을 보인다.
- 인스펙터 맨 위 "선택한 세션" 칸에 그 세션의 사용량·예상치를 둔다. 이벤트를 고르지 않아도 보인다(Frontdoor를 누르면 바로 보임).
- Frontdoor 줄에는 상태 배지 "실행 중"과 따로, 그 작업 전체(Frontdoor + Worker)의 "작업 토큰"과 진행 중인 턴들의 합 "이번 턴 N"을 보인다. 진행 중인 턴이 모두 토큰 전이면 "이번 턴 집계 중". 일부만 빠졌으면 도움말: "토큰이 턴 끝에 확정되는 세션 N개는 합계에서 빠져 있습니다." 좁으면 우선순위가 낮은 배지(작업공간 → 작업 토큰 → Worker 수)부터 뺀다. 배지는 줄바꿈하지 않는다.

## 7. 관측 가능 범위와 경고
- hook 또는 Gateway 스트림으로 바로 갱신되는 세션에 "실시간" 배지(Gateway 세션 포함). 종료된 세션·지난 기록(연 기록, 대기 유지 시간이 지나 기록으로 옮긴 세션 — 현재 스냅샷에 없는 세션)에는 붙이지 않는다.
- 권한 대기를 볼 수 없는 **살아 있는** 세션(hook 꺼진 Claude·Grok)에 "권한 대기 감지 불가 (hook 꺼짐)". 종료·지난 기록에는 쓰지 않는다.
- read_only/ask Codex Gateway 세션에 "읽기 전용 부분 적용" 경고 — 편집 불가처럼 보이게 하지 않는다.

## 8. Hook과 설정 변경
- 사용자 설정 파일은 **동의 후에만** 바꾼다(온보딩, 또는 업데이트 후 한 번 묻기). "사용 안 함"은 범위가 바뀌기 전까지 기억한다.
- 설정 탭은 "등록됨 · 마지막 수신 …"으로 실제 수신 여부를 보여 준다. 등록만으로 "연결됨"이라고 하지 않는다.
- Codex에는 정보가 있는 이벤트만 등록한다(터미널 hook 로그 최소화).

## 9. 레이아웃
- 메트릭 카드는 세 장: "활성 Frontdoor", "실행 중 세션 · Gateway n / 로컬 n", "미응답 요청". Gateway 버전·build·보관 이벤트 수는 연결 줄 오른쪽 ⓘ에 둔다.
- 인스펙터 기본은 선택한 세션(사용량)과 선택 이벤트다. "Gateway 상태", "미응답 요청 N", "태스크 N"은 접힌 채로 시작하고, 펼친 상태는 앱이 실행되는 동안 기억한다.
- 대시보드 좌측(세션 목록)·우측(인스펙터)은 툴바에서 숨기고 보일 수 있고, 선택은 저장된다.
- 창이 좁으면 인스펙터부터 접고, 더 좁으면 세션 목록도 접는다. 접힌 패널은 버튼으로 바로 펼칠 수 있다.
- 둘 다 들어가지 않는 폭에서 한 패널을 강제로 펼치면 다른 패널의 강제 펼침은 풀린다. 버튼 tooltip이 결과를 말한다("인스펙터를 접고 세션 목록 펼치기").
- 사이드바 "활성만"(tooltip "실행 중이거나 대기 유지 시간 안에 있는 세션만 보입니다")이 Frontdoor를 숨기면 "활성만 보기로 N개 숨김 · 전체 보기", 목록이 비면 "진행 중인 Frontdoor가 없습니다". Frontdoor가 아예 없으면 "실행 중인 Frontdoor 없음 · 터미널에서 claude/codex/grok을 실행하면 표시됩니다".

## 10. 기록
- 기록 위치·용량·보관 기간을 설정 탭에 보여 주고 "기록 지금 삭제"를 제공한다. 보관 기간 0은 디스크에 남기지 않음.
- "지난 기록"은 스크롤로 계속 불러온다. 목록은 최근 500개까지 두고, 그 뒤로는 더 불러오지 않는다. 연 기록은 지금 연 것과 최근에 연 5개까지만 이벤트를 메모리에 두며, 그보다 오래 전에 연 기록은 다시 열 때 새로 불러온다.

## 12. 접근성과 tooltip
- 아이콘만 있는 버튼은 모두 `.accessibilityLabel`을 tooltip과 같은 문구로 단다.
- 보이는 라벨이 없는 Toggle/Picker(세션 설정)에는 설정 이름을 접근성 라벨로 단다.
- 시퀀스 다이어그램의 접근성 라벨: "이벤트 시퀀스. Frontdoor와 Worker의 호출·응답".
- 빈 `.help("")`을 두지 않는다. 이름 되돌리기 tooltip은 어디서나 "자동 이름으로 되돌리기", 알림 종은 "최근 알림·오류 N건 보기".

## 13. 메뉴바
- 메뉴바 아이콘 옆에는 사용자를 기다리는 단계 수(`권한 N` 우선, 없으면 `입력 N`), 없으면 `실행 N`만 쓴다. 아무것도 없으면 아이콘만.
- 팝오버는 **작업(Frontdoor)당 카드 한 장**이다. 카드 안에서 세션은 위임 순서(Frontdoor → Worker → 하위 Worker, `parentSessionId` 기준, 모르면 Frontdoor 아래)로 들여쓰기하고, 단계마다 아이콘 · 이름 · 역할 · 상태 문구(§3) · 실행 중이면 경과 시간을 쓴다.
- 카드 순서: 권한 대기 > 입력 대기 > 오류 > 실행 중. 사용자를 기다리는 카드는 오래 기다린 것이 위, 실행 중은 최근 활동이 위. 대기·종료 작업은 "대기 중 작업 N개"로 접는다.
- 가장 급한 단계에 `← 현재`, 대기 이유(승인할 도구 · 질문), 카드 아래에 현재 단계와 "이번 턴 N / 예상 약 X"를 보인다(Grok은 "이번 턴 집계 중").
- 단계가 많으면 앞쪽과 주의가 필요한 단계만 남기고 "+N개 단계 더 있음"으로 접는다. 기다리는 단계는 접지 않는다.
- 카드를 누르면 그 작업, 단계를 누르면 그 세션이 선택된 대시보드를 연다.
- 연결 상세(스트림, 마지막 갱신, 미응답 요청)는 ⓘ로 접어 둔다. hook 동의가 필요하면 "실시간 모니터링이 꺼져 있습니다 · 켜기…"를 보인다.
