# 모니터링 UX 정책

Claude · Codex · Grok · Gateway 세션을 **같은 규칙으로** 보여 주기 위한 기준. 화면·문구를 바꿀 때 이 문서에 먼저 맞추고, 검수는 이 목록으로 한다.

## 1. 역할 (Frontdoor / Worker)
- Frontdoor는 사람이 직접 연 세션, Worker는 다른 세션이 연 세션이다.
- Gateway가 한 번이라도 보고한 세션은 Gateway가 닫은 뒤에도 **Frontdoor로 승격하지 않는다** (worker transcript가 로컬 세션으로 남아도 동일).
- 부모를 모르는 로컬 세션만 Frontdoor 후보가 된다. provider가 다른 부모도 그 provider 아이디로 연결한다.
- Gateway가 본 worker id는 `~/.acp-gateway/agenlynk/workers.json`에 남겨, sidecar 재시작이나 기록 보관 0 이후에도 Frontdoor가 되지 않는다. (알려진 한계: 예전에 worker였던 Claude 세션을 터미널에서 `--resume`하면 로컬 Frontdoor로 보이지 않는다.)
- opener를 모르는 Gateway worker는 Frontdoor로 올리지 않되 숨기지도 않고 **연결 미확인 Worker** 한 그룹에 둔다.

## 2. 이름
- provider는 **아이콘**으로 보여 준다(Claude / Codex / Grok). 이름 텍스트에 provider를 반복하지 않는다.
- Frontdoor 이름: 사용자 지정 > 작업 폴더명 > 지정 제목.
- 세션 이름: 사용자 지정 > CLI 자체 제목(Claude ai-title) > 최근 프롬프트 앞 60자 > 작업 폴더명 > "새 세션".
- 원시 세션 id(`local:codex:01a0…`)는 이름으로 쓰지 않는다. tooltip에만 둔다.
- 사용자는 Frontdoor와 세션 모두 이름을 바꿀 수 있고(연필 / 레인 우클릭), 비우면 자동 이름으로 돌아간다.

## 3. 상태 문구
| status | 문구 |
|---|---|
| running | 실행 중 |
| waiting_permission | 권한 대기 (Codex 샌드박스 승인 포함) |
| waiting_input | 입력 대기 (에이전트가 사용자에게 질문) |
| idle | 대기 |
| closed | 종료 |
| error | 오류 |
- 원문 status 문자열(`waiting_permission` 등)을 화면·tooltip에 노출하지 않는다. 목록에 없는 status는 "알 수 없음".
- 메뉴바도 같은 표를 쓴다: 권한 대기와 입력 대기를 합쳐 "응답 대기"로 쓰지 않는다.
- 활동 머리글: idle은 "대기 · 다음 입력을 기다림", closed는 "종료됨". 둘 다 "완료"로 쓰지 않는다.
- 권한 요청 결과 어휘는 approved / denied / cancelled로 고정하고 권한 요청 대기 / 승인됨 / 거부됨 / 취소됨으로 보인다. 결과를 알 수 없는 응답은 "응답됨". 거부·취소를 "완료"로 보이지 않는다.
- 판정 근거: hook은 다음 이벤트(도구 실행 = 승인, PermissionDenied = 거부, 턴 종료 = 취소), Gateway는 고른 option의 kind(allow_* / reject_*, 선택 없음 = 취소).
- 도구 결과도 성공/실패를 구분한다(Codex의 non-zero exit, 샌드박스 거부는 실패).

## 4. 세션 수명
- 턴을 마친 세션은 **대기** 상태로 `대기 세션 유지 시간`(기본 30분, Gateway idle unload와 같음) 동안 남긴다. 기준 시각은 마지막 활동(턴 종료) 시각이다. 재사용 시 cold start를 피하기 위함.
- 목록에서 빠진 세션이 메모리 로그에 남는 시간도 같은 값이다. 그보다 오래된 것은 "지난 기록"에서 본다.
- 종료가 확인된 세션(SessionEnd hook, 프로세스 종료, Gateway session_closed)은 바로 기록으로 옮긴다.
- 이 규칙은 provider와 hook 유무에 관계없이 같다.

## 5. 타임라인
- 한 줄로 계속 스크롤한다(페이지 없음). 맨 아래 표식이 보이면 새 이벤트를 따라가고(마지막 이벤트가 바뀔 때마다, 같은 도구 그룹이 늘어날 때 포함), 위로 올리면 멈추며 "최신으로"로 돌아간다. 맨 위에 닿으면 이전 기록을 더 불러오고, 불러오기 전 맨 위에 있던 **이벤트**에 화면을 고정한다.
- 도구 호출은 **짧은 헤더**(도구명 + 인자 앞 ~30자 + 상태 기호)로만 보여 주고, 출력은 인스펙터에서 본다.
- 같은 턴에서 연속된 도구 호출은 대표 한 줄로 묶는다: "도구 N개 · 실행 중: …" (실행 중인 것, 없으면 마지막). 실패가 있으면 개수를 붙인다. 턴을 모르는 호출끼리는 묶지 않는다.
- 권한 요청, 메시지, 생각, 턴 경계는 묶지 않는다.
- 턴이 끝나면 열린 도구 호출은 턴 결과(완료/취소)로 닫는다 — 스피너가 남지 않는다.
- 이벤트 종류는 한국어로: 턴 시작, 턴 종료, 사용자 입력, 응답, 생각, 도구, 권한 요청, 입력 요청, 서브에이전트, 계획, 컨텍스트 압축, 오류.

## 6. 사용량
- "세션 누적 토큰"(입력은 cache 포함 · 출력)과 "최근 요청 컨텍스트"를 구분해 쓴다.
- 창 크기를 모르면(Claude) 게이지 대신 "최근 요청 컨텍스트 N 토큰 (창 크기 미제공)".
- transcript 일부만 읽은 합계는 `+`를 붙이고 tooltip으로 설명한다.
- **작업 중 사용량과 예상치**: 진행 중인 턴은 "이번 턴 N 토큰 · M분째". 완료된 턴이 2개 이상이면 "예상 약 X (지난 k턴 중앙값)"와 진행 막대(초과 시 주황)를, 컨텍스트 창을 알면 "컨텍스트 약 K턴 여유"(최근 턴당 증가량 중앙값 기준)를 보인다.
- Grok은 턴이 끝나야 토큰을 확정하므로 진행 중에는 "이번 턴 집계 중"으로 쓴다(추정하지 않는다).
- Frontdoor 줄에는 그 작업 전체(Frontdoor + Worker)의 "작업 토큰"과 진행 중인 턴들의 합 "진행 중 N"을 보인다.

## 7. 관측 가능 범위와 경고
- hook 또는 Gateway 스트림으로 바로 갱신되는 세션에 "실시간" 배지(Gateway 세션 포함).
- 권한 대기를 볼 수 없는 세션(hook 꺼진 Claude·Grok)에 "권한 대기 감지 불가 (hook 꺼짐)".
- read_only/ask Codex Gateway 세션에 "읽기 전용 부분 적용" 경고 — 편집 불가처럼 보이게 하지 않는다.

## 8. Hook과 설정 변경
- 사용자 설정 파일은 **동의 후에만** 바꾼다(온보딩, 또는 업데이트 후 한 번 묻기). "사용 안 함"은 범위가 바뀌기 전까지 기억한다.
- 설정 탭은 "등록됨 · 마지막 수신 …"으로 실제 수신 여부를 보여 준다. 등록만으로 "연결됨"이라고 하지 않는다.
- Codex에는 정보가 있는 이벤트만 등록한다(터미널 hook 로그 최소화).

## 9. 레이아웃
- 대시보드 좌측(세션 목록)·우측(인스펙터)은 툴바에서 숨기고 보일 수 있고, 선택은 저장된다.
- 창이 좁으면 인스펙터부터 접고, 더 좁으면 세션 목록도 접는다. 접힌 패널은 버튼으로 바로 펼칠 수 있다.

## 10. 기록
- 기록 위치·용량·보관 기간을 설정 탭에 보여 주고 "기록 지금 삭제"를 제공한다. 보관 기간 0은 디스크에 남기지 않음.
- "지난 기록"은 스크롤로 계속 불러온다.
