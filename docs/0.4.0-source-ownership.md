# AgenLynk `src/` 소유권 분류

이 목록은 Phase 4 완료 후의 0.4.0 소유권 기준선이다. Gateway 구현은 저장소에서 제거되며 `gateway.lock.json`에 고정된 공식 release artifact만 빌드 시 소비한다.

## Gateway fork

아래 구현은 모두 AgenLynk에서 제거되었다. 빌드 결과의 `gateway-seed/gateway/`는 `agent_gateway` v1.4.0 artifact에서만 생성된다.

```text

agent-updates.js

early-shutdown.js
frontdoor-context.js

process-environment.js

socket-flow.js

```

## AgenLynk sidecar

앱과 함께 버전이 움직이며 `Contents/Resources/sidecar`에서 실행한다.

```text
sidecar/src/local-agents/*
sidecar/src/local-monitor.js
sidecar/src/local-transcript.js
sidecar/src/projection/monitor-state.js
sidecar/src/server/monitor.js
```

이 namespace는 `sidecar/package.json`의 `@creverse-ai-lab/agenlynk-sidecar` 패키지와 `agenlynk-sidecar` bin으로 실행되며 Gateway와 별도의 version/build ID를 가진다.

## AgenLynk app runtime integration

Gateway 구현이 아니라 app packaging/install/activation 경계다. artifact 전환 후에도 역할을 검토해 유지하거나 Swift `GatewayRuntimeManager`로 옮긴다.

## App-owned sidecar services

Gateway wire가 아닌 앱 설정·공식 agent catalog·설치 상태 기능은 `sidecar/src/app/`이 소유한다. Gateway 연결은 `sidecar/src/gateway/client.js`가 활성 runtime의 `gateway-client/index.js` public entrypoint만 로드한다.

```text
acp-registry.js
agent-catalog.js
config.js
fs-paths.js
gateway-settings.js
install-state.js
providers.js
```

## 이동 규칙

- sidecar는 `gateway/client.js` 밖에서 Gateway code를 동적 로드하지 않으며 private package subpath를 import하지 않는다.
- app runtime integration은 공식 release manifest의 files 인벤토리와 `gateway.lock.json` identity/digest를 함께 검증한다. 공식 Mach-O를 재서명할 때만 codesign-only transform을 명시적으로 기록한다.
- `gateway_config`, agent catalog, app runtime update는 1.4.0 Gateway public wire라고 가정하지 않는다.
- `macos/scripts/build-app.sh`는 `gateway-seed/`와 `sidecar/`를 별도 resource root로 조립한다.
- Gateway daemon은 설치된 `current/gateway`, sidecar는 앱의 `Resources/sidecar`에서 실행한다.
